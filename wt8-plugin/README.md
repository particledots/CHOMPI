# ipmohc (formerly WT8) — wavetable synth plugin built from the CHOMPI WAVE engine

An 8-voice wavetable synthesizer (AU / VST3 / Standalone) that runs the **CHOMPI WAVE 1.0** synth engine
from the open-source CHOMPI release (https://github.com/CHOMPI-Club/CHOMPI, MIT) inside a JUCE plugin.
Not affiliated with or endorsed by Chase Bliss / CHOMPI Club. "CHOMPI" is their trademark; this project
uses a different name on purpose.

**Status: v0.20 (filter envelope, more resonance in the new filter types), on top of v0.19 (filter type, key tracking, velocity), v0.18 (saved step view), v0.17 (LFO shapes), v0.16 (slot chaining), v0.15 (layout) and v0.14 (commit 940b333).** The engine, parameters, MIDI, state save/restore, wavetable loading and the step
sequencer are covered by headless tests that run on Linux and again on the macOS build server (see Tests). The
Audio Unit is built there as a universal binary (Apple silicon and Intel) and has been tried in Logic Pro by its
owner on an Intel Mac (macOS 12.7.6) and an M4 Mac mini (up to and including v0.19; v0.20's filter envelope has not been tried in Logic yet). The **VST3 and Standalone builds have not been tried in
a host.** Each section below says which version added a feature.

## What's in it
- 8 voices: wavetable oscillator (7 tables x 33 frames) -> resonant filter -> amp envelope
- 2 LFOs (pitch, filter; v0.17: each with a choice of shape), delay <-> reverb macro, compressor <-> saturation macro, pan, gain
- Custom panel (v0.2): knobs grouped by signal flow (oscillator, envelope, filter, LFO, effects, output), value readouts, double-click a knob to reset it, double-click a readout to type a value, resizable window. All controls are automatable in Logic.
- Since v0.8 / v0.9: presets (a built-in INIT, 14 starter presets, your own saved presets) and 16 pattern slots. Since v0.10 / v0.11: loading your own wavetables. Since v0.12: a picture of the selected table (all described in the sections below).
- Not there yet (ideas only, nothing built): more than 7 table slots, random / sample-and-hold LFO shapes, a tempo-synced delay time, an automatable pattern-slot parameter. (MIDI clock is not needed: the sequencer follows Logic's tempo.)

## Build on your Mac (Apple silicon or Intel)
One-time setup:
1. Install Xcode from the App Store, open it once, accept the license. Then in Terminal: `xcode-select --install`
2. Install Homebrew (https://brew.sh), then: `brew install cmake`

Build (in Terminal, from this folder):
```
cmake -S . -B build -DCMAKE_BUILD_TYPE=Release
cmake --build build --config Release -j 8
```
The first configure downloads JUCE (needs internet, a couple of minutes). A successful build copies:
- `~/Library/Audio/Plug-Ins/Components/ipmohc.component`  (Audio Unit — this is the one Logic uses)
- `~/Library/Audio/Plug-Ins/VST3/ipmohc.vst3`

Check it: `./build/render_test wavetables build/out.wav` and `./build/plugin_test` should both print PASS.
Validate as an Audio Unit: `auval -v aumu Ipmo Ptdt`. Then in Logic: a Software Instrument track ->
Instrument slot -> AU Instruments -> particledots -> ipmohc. If it doesn't show up, restart Logic
(Logic Pro > Settings > Plug-in Manager > Reset & Rescan Selection).

## Step sequencer (v0.7)
32 steps, timed from Logic's tempo. Modelled on the CHOMPI WAVE sequencer (record notes as steps, rests, loop, gate, mute).
- **Record:** press REC, then play notes: each note becomes the next step (with its velocity). REST adds a gap, DEL removes the last step, CLEAR empties the pattern. While REC is armed the pattern does not play.
- **Edit:** click a step to toggle note/rest (clicking past the end extends the pattern); drag a step up/down or use the mouse wheel to change its pitch.
- **Play:** PLAY starts it from step 1 at Logic's tempo, any time (SYNC = Free). With SYNC = Logic it plays whenever Logic's transport plays, locked to the bar position, and PLAY is greyed out. Looping/relocating in Logic restarts cleanly.
- **STEP** = step length: 1/4, 1/8, 1/16, 1/32 and triplets (1/4T ... 1/32T). **GATE** = how much of each step the note sounds (100% = legato). **MUTE** silences it (immediately, including a sounding note).
- Sequencer notes and played notes are separate sources, as in the firmware: you can play over the pattern.
- The pattern is saved with the Logic project. A project never starts playing the sequencer just because it was opened (PLAY is switched off on load).
- **DIRECTION** (v0.4): Forward, Backward, Pendulum or Random. Pendulum plays 1-2-3-2-1-2-3...; switch **ENDS x2** on and the two end steps play twice (1-2-3-3-2-1-1-2-3...). Random picks any step each time (the same step can come up twice in a row). With SYNC = Logic the step is always worked out from Logic's position, so jumping around in the project gives the same result as playing up to that point. The pattern repeats every N steps (Forward, Backward), 2N steps (Pendulum with ENDS x2) or 2N-2 steps (Pendulum without it), where N is the loop length; it lines up with Logic's bars whenever that is a whole number of bars (16 steps of 1/16 = one bar), otherwise it drifts against them, which is the off-kilter effect.
- **LOOP** (v0.4): plays only the first N steps of the pattern (ALL = the whole pattern; a number larger than the pattern also plays the whole pattern). The recorded pattern is not changed, so a 7-step loop can run against a longer pattern.
- **Probability** (v0.4): every step has its own chance of playing, and the **PROB** knob scales all of them (global x step). A step that misses its roll behaves like a rest: it stays silent and the previous note still ends on time. Switch the grid to the **PROB** lane (EDIT: PITCH / PROB) to see and edit the per-step values: drag a step up/down (1 pixel = 1 %) or use the mouse wheel (5 % per notch); double-click sets it back to 100 %. Rests have no probability.
- **SEED** (v0.4): RANDOM = different choices every time playback starts (and on every pass of a Logic cycle). A number = the same choices every time, so a bounce matches what you heard. Random direction uses the same seed.
- Saving: the pattern is saved as before (`60:100,r,67:80`); a step with a probability other than 100 gets a third number (`60:100:75`). Projects saved by v0.3 load unchanged, and a setting that did not exist yet when the project was saved comes back at its default (PROB 100 %, Forward, LOOP ALL, SEED RANDOM).
- **SCALE / ROOT** (v0.5): snaps every note the sequencer plays to a scale. OFF by default. The menu has the same 28 scales, in the same order and with the same names, as the Logic Scripter scripts (Major, the church modes, harmonic/melodic minor, exotic and pentatonic scales, whole tone, octatonic, Chromatic...); ROOT sets the key (C..B). A note between two scale tones snaps to the nearest one, and exactly halfway it goes down. This happens as each note is played: the recorded pattern is never changed, so you can switch the scale off or change it and the same pattern comes back. Live MIDI you play is not quantized. With a scale set, dragging a step in the PITCH lane or using the mouse wheel moves it in scale steps instead of semitones (the stored note is what changes there).
- **MIDI XPOSE** (v0.5): when on, the last key you play into the plugin transposes the whole pattern: **C3 = no shift**, D3 = up 2 semitones, A2 = down 3. It **latches**: the pattern stays shifted until you play another key or press **RESET**, which puts it back to 0. The readout next to the button shows the current shift (dim while MIDI XPOSE is off, because then the pattern plays as recorded). The transpose is added first and the result is then snapped to the scale, so a transposed pattern stays inside the scale you set (the scale root does not move with the key). The key itself is silent while the pattern is running and sounds as normal when it is not. While REC is armed keys record steps as before and do not transpose. The shift is saved with the project; notes are kept inside MIDI 0-127. The grid keeps showing the stored notes, not the transposed ones.
- **Per-step expression** (v0.6): the grid has seven lanes, chosen with the **EDIT** buttons: PITCH, PROB, RATCH, GATE, ACCENT, OCT, COND. Each step has its own value in every lane; a step you never touched plays exactly as before. Rests have no values (they keep the ones they had, so a note turned into a rest and back comes back unchanged).
  - **RATCH** (1-8): the step is played as that many evenly spaced repeats inside its own length. Drag up/down (12 pixels per repeat) or use the mouse wheel; double-click = 1. Each repeat is gated by the step's gate. Probability, trigger condition and octave jump are decided once per step, so a ratchet plays all its repeats or none. MUTE, stopping, REC and a Logic relocate cancel the repeats that have not started yet.
  - **GATE** (per step): the step's own gate in % of its length; 100 = legato. Without its own value a step follows the **GATE** knob (the lane shows the knob's value dimmed). Drag (1 pixel = 1 %) or wheel (5 % per notch); double-click = follow the knob again.
  - **ACCENT** (per step) and the **ACCENT** knob: click a step to accent it. An accented step plays louder by the knob's amount: its velocity + amount x 127, never above 127 (default 0.30 = about +38).
  - **OCT** (per step) and the **OCT JUMP** menu: each step has a chance (0-100 %, drag or wheel, double-click = 0) of jumping by the octave(s) set in the menu: up 1, down 1, up or down 1, up 2, down 2, up or down 2. A jump keeps the note's pitch class, so it still fits the scale. It is added together with the MIDI XPOSE transpose before the note is snapped to the scale, and the result is kept inside MIDI 0-127. Like probability and random direction it uses the SEED: a number repeats the same jumps every time.
  - **COND** (trigger condition): "pass a of every b", for b from 2 to 8 (36 choices, ALL = every pass). Drag (6 pixels per choice) or wheel; double-click = ALL. A **pass** is one trip through the loop: N steps (Forward, Backward, Random), 2N-2 steps (Pendulum) or 2N steps (Pendulum with ENDS x2), where N is the LOOP length. A step that is not due behaves like a rest (the previous note still ends on time). The pass is worked out from the step counter, so with SYNC = Logic it depends only on Logic's position (jumping around gives the same result as playing up to that point), and every Logic cycle jump starts counting again from pass 1. With SYNC = Free it counts from when PLAY was pressed.
  - Order of decisions for a step: trigger condition, then probability (global x step), then the octave-jump roll, then transpose, then the scale.
- **SWING** (v0.6): 50-75 %, MPC style: every second step (the 2nd, 4th, ...) starts late. 50 = straight, 66.7 = triplet feel (a third of a step late), 75 = half a step late. It works with every STEP length. A step lasts until the next step starts, so gates and the repeats of a ratchet are measured against that real length (a swung step before a late one is longer, the late one is shorter). Direction, probability and conditions are not affected, only the timing.
- **Layout (v0.15):** the sequencer controls are in six rows (v0.16 adds a seventh, CHAIN, below), one job per row, each with a caption at the left so the controls line up: **EDIT** (REC, REST, DEL, CLEAR | RANDOM), **PLAY** (PLAY, MUTE, RETRIG | SYNC, STEP | AT LOOP END), **DIRECTION** (direction, ENDS x2 | OCT JUMP), **SCALE** (scale, ROOT | MIDI XPOSE), **LANE** (the lane buttons | GRID, RING, 2 RINGS) and **PATTERN** (the 16 slots, COPY). Thin lines separate the groups inside a row. The window is 840 x 934 (v0.14: 840 x 898) and resizes between 630 x 700 and 1260 x 1401 (v0.16: 840 x 970, 630 x 728 to 1260 x 1455; v0.17 keeps this size). No function, parameter or saved-project change. The drop-down boxes now keep a text area at small window sizes: JUCE reserves a fixed 30 px for the arrow, so at the old 630 px minimum SYNC and STEP showed only `...` and DIRECTION `Pendu...`; the arrow area now shrinks with the box (the 30 px high boxes of the sequencer rows look the same as before at the default size; the preset box in the header, 26 px high, has its arrow 4 px further right).
- **Filter envelope** (v0.20): two knobs in the ENVELOPE group, next to the amp ATTACK / RELEASE: **FILT ENV** (-100 % to +100 %, 0 = off, the default) and **FILT DECAY** (10 ms to 4 s, exponential, default 40 %). At every note start the filter envelope jumps up almost at once (2 ms) and falls back to nothing over FILT DECAY (no sustain; it restarts with each note, including sequencer steps and ratchets). It moves the filter's frequency by up to 4 octaves at its peak: **positive FILT ENV opens the filter** at the start of a note (a pluck / "wow" sweep), **negative closes it** and lets it recover. It works together with KEY and VEL and with the filter LFO, in every filter type. With the DJ filter it acts on whichever half is working, and with the DJ cutoff in the middle (open) there is nothing to open, so it changes nothing; the DJ filter also smooths its own cutoff slowly (about 0.1 s), so a short envelope sounds rounder there than in the Low-pass / High-pass / Band-pass types. New parameters *Filter Envelope Amount* and *Filter Envelope Decay* (automatable, saved with the project, listed after the older ones); a project from before v0.20 opens with FILT ENV 0, which sounds as before (the v0.18 recording test still passes with a difference of 0). Presets store them from v0.21. **Resonance in the new filter types is about 17 % stronger from v0.20** (around the default and mid positions); the boost fades out toward the top of the knob, because the filter core becomes unstable at an effective resonance of about 1.0 (measured), so the very top of the knob is hardly louder than before. The DJ filter's resonance is unchanged. To make room, the two top rows now hold 12 knob cells each, so the knobs are a little smaller than in v0.19 (the top row's, a bit more), and the LOAD / RESET pair under WAVETABLE reaches slightly to the right.
- **Filter type, KEY and VEL** (v0.19): a drop-down under CUTOFF / RESONANCE chooses the filter: **DJ** (the default, exactly the filter the plugin always had: low-pass below the middle of the CUTOFF knob, high-pass above it, the middle is open), **Low-pass**, **High-pass** or **Band-pass** (one two-pole filter that the whole CUTOFF range sweeps, cubic, roughly 15 Hz to 17 kHz at 48 kHz; the filter is the plugin's own simple design, its resonance is gentle rather than screaming). Two new knobs in a new **FILTER MOD** group: **KEY** (0-100 %) makes the filter follow the pitch of each note, 100 % = octave for octave, measured from C3 (a note above C3 opens the filter, one below closes it; approximate, because the cutoff scale is not linear in Hz); **VEL** (0-100 %) makes a softer note darker: at 100 % a velocity-1 note has its filter 4 octaves lower than a velocity-127 note, and a full-velocity note is unchanged. In the DJ filter both act on the cutoff of whichever half is working, so with the DJ cutoff in the middle (open) they change nothing. Type, KEY and VEL are saved with the project and are automatable (new parameters *Filter Type*, *Filter Key Tracking*, *Filter Velocity*, listed after the older ones); a project from before v0.19 opens with DJ, 0, 0, which sounds as before (tested against a recording of the v0.18 build). Presets store these from v0.21. The Filter and LFO knob groups give up some height to the boxes, and the row with the LFO is now four groups wide, so its knobs are a little smaller (the DELAY / REVERB label is a bit smaller too). As before, the cutoff in Hz depends on the host sample rate (the filter coefficients are per sample), so a project moved between 44.1 and 96 kHz will have a different cutoff in Hz.
- **LFO shape** (v0.17): a drop-down under each pair of LFO knobs (left: the pitch LFO, right: the filter LFO) chooses its shape: **Triangle** (the default, and what both LFOs always were), **Sine**, **Saw down**, **Saw up** or **Square**. Depth and rate work as before; a square LFO jumps between its two extremes, so a filter LFO set to Square at a high depth will click-sweep audibly (that is the shape, not a bug). The two shapes are saved with the project as the parameters *Pitch LFO Shape* and *Filter LFO Shape* (automatable; new parameters, so Logic lists them after the older ones). A project from before v0.17 opens with both on Triangle, i.e. sounding as before. Presets store the shapes from v0.21. The LFO knobs are slightly smaller than before to make room for the boxes. There is no random / sample-and-hold shape (the bundled DaisySP oscillator has none).
- **CHAIN** (v0.16): a seventh row under PATTERN. **CHAIN** (OFF/ON) makes the sequencer walk through the pattern slots by itself. Each slot plays a number of *passes* (a pass is one trip through the pattern as played: LOOP length, direction and ENDS x2 included), set per slot with the **SLOT n PLAYS** box (1x-16x, default 1x; the box edits the slot that is currently selected). After the last pass the next slot with a pattern starts, exactly on the pass boundary (to the sample, also in a Logic cycle); after slot 16 it wraps to slot 1; empty slots are skipped; if no other slot has a pattern the current one keeps looping. The readout at the right of the row shows the order, e.g. `1 x1 > 3 x1 > 6 x2 > ...`. Counting starts at the next pass start after CHAIN is switched on. Details: a queued AT LOOP END switch wins over the chain (and restarts the count); RETRIG, clicking a slot, STEP 1, stop/start and CHAIN off reset the count; a Logic relocate does not. The chain on/off and the 16 counts are saved with the project (older projects load with CHAIN off and every count 1); they are not automatable.
- **GRID / RING / 2 RINGS views** (v0.7): the **GRID / RING / 2 RINGS** buttons at the end of the LANE row (called EDIT before v0.15) choose how the steps are shown. GRID is the 2 x 16 cells. RING puts the steps on one ring of 16 buttons (step 1 at the top, clockwise), with the page buttons **1-16 / 17-32** beside it for steps 17-32 (a small amber dot on a page button means the playing step is on that page). **2 RINGS** shows all 32 steps at once on two rings side by side, laid out as a figure-eight: steps 1-9 on the left ring from 9 o'clock round to 3 o'clock, steps 10-25 once all the way round the right ring (starting at its 9 o'clock), steps 26-32 on the bottom arc of the left ring, then step 1 again; faint arrows mark the two hops between the rings (9 to 10 and 25 to 26). It is still ONE sequence with ONE playhead (one light moves at a time, hopping between the rings), not two independent sequencers; the layout is fixed by step number, so with a short pattern or LOOP only part of the rings is used (RING is the better picture for loops of 16 or fewer). All of these are only different views of the same pattern: nothing about playback, saving or the parameters changes, and the EDIT lane buttons choose the lane in every view. The value of the chosen lane is the fill level of each button (like the bars in the grid); the playing step has the amber outline, a brighter fill and a soft glow; steps beyond the **LOOP** length are dimmed (they stay editable); empty slots past the end of the pattern are outlines. The middle of a ring shows the exact value for the step under the mouse or being dragged ("STEP 6 / PROB / 70%", "REST" for a rest, "FOLLOWS KNOB" for a step gate that follows the GATE knob). In RING, with the mouse elsewhere, it describes the playing step, and when nothing plays it just names the lane. In 2 RINGS the ring that holds the step under the mouse describes it, and the other ring describes the playing step if that is on it, otherwise it just names the lane. Editing is the same as in the grid: in the PITCH lane click toggles note/rest (clicking an empty slot extends the pattern) and a vertical drag or the wheel changes the pitch; in the other lanes a vertical drag, the wheel and a double-click work as described for each lane above. The window is taller than in v0.6 to give the rings room (v0.7: 840 x 862, was 840 x 762; v0.9 adds one row for the pattern-slot buttons: 840 x 898); it is still resizable with the same proportions. Since v0.18 the chosen view (GRID, RING or 2 RINGS) is saved with the project and the editor opens in it; a new instance, and a project saved before v0.18, opens in 2 RINGS (it was GRID before). The page of the single RING (1-16 / 17-32) is still not saved: it starts on 1-16. The view is not a parameter and cannot be automated.
- **Pattern slots** (v0.8, buttons and COPY in v0.9): the row of **16 numbered buttons** just above the steps (label PATTERN) holds 16 patterns inside the project. The lit button is the slot being played; a small dot under a number means that slot holds a pattern, and an empty slot is silent (so you can record a new pattern in it). Clicking a button plays that slot from now on. The slot you leave is kept exactly as it was, in all views (GRID, RING, 2 RINGS). While the sequencer runs in Free sync, a new pattern starts from step 1 (a note that is sounding ends through its gate); in Logic sync the position still follows Logic's bar. Only the steps belong to a slot: direction, loop, rate, scale, swing, accent, OCT JUMP and the MIDI transpose are shared by all slots. REC, REST, DEL and CLEAR work on the current slot. The slots are saved with the project; a project saved by an older version opens with its pattern in slot 1 and the other slots empty (an older version opening a v0.8 / v0.9 project sees the current slot's pattern).
- **COPY** (v0.9): at the right end of the slot row. Press COPY (the label changes to "COPY n TO" and the button to CANCEL), then click the slot to copy the current pattern into; the current slot keeps playing and the copy waits in the target slot (click the target afterwards to play it and make a variation). If the target already holds a pattern you are asked first (REPLACE / CANCEL). Clicking the current slot, or CANCEL, leaves COPY without doing anything. COPY is greyed out while the current slot is empty. A copy has every per-step value of the original (probability, ratchet, gate, accent, octave chance, condition) and is saved with the project like any slot.
- **RETRIG** (v0.13): in the PLAY row, right after MUTE (v0.13 and v0.14 had it in row C after the OCT JUMP menu). Sends the sequence back to its step 1 while it plays. It works in **Free sync only** and is greyed out with SYNC = Logic (there Logic's bar position decides the step). It acts at the **next step boundary**, not mid-step, so the timing grid is kept: the note that is sounding finishes through its gate (and a ratchet plays out), and the next step played is step 1. Pressing it twice before that boundary is the same as pressing it once. After it, the pass count (COND), Pendulum direction and Random direction start again as if PLAY had just been pressed (with SEED = RANDOM the random choices are new, as at PLAY). Pressing it while nothing plays does nothing.
- **AT LOOP END** (v0.13): a switch at the right end of the PLAY row (v0.13 and v0.14: row C). **Off (the default, and what every older project has): clicking a slot switches at once, exactly as in v0.12.** **On:** while the sequence runs, clicking another slot *queues* it: that button gets an amber outline, the label above the slots reads **NEXT n**, and the current slot keeps playing until the current pass through the loop ends (one pass = as defined for COND: N steps for Forward/Backward/Random, 2N-2 for Pendulum, 2N for Pendulum with ENDS x2). Then the new pattern starts from its step 1 and the pass count restarts. Clicking another slot while one is queued replaces the queue; clicking the playing slot cancels it; switching AT LOOP END off cancels it. If the sequence is not running (stopped, REC armed) or the target slot is empty there is nothing to wait for and the switch happens at once. If RETRIG is pressed while a switch is queued, the switch happens at that boundary and the loop is counted from there. In Logic sync the new pattern starts from step 1 at the loop end and then follows Logic's bar as before; a relocate in Logic restarts the count. COPY writes into a queued slot correctly. The switch is saved with the project (a project without it opens with it off); the queued switch itself is **not** saved, and loading a project cancels any queue. The switch is not an automatable parameter. The slot you leave is kept exactly as it was, also when the swap happens just before you save the project.
  - Correction to the v0.8 slot text above: switching a slot does *not* let the sounding note finish through its gate; in v0.8-v0.12 an immediate switch (AT LOOP END off) cuts the sounding note at once, as the code's `restart()` does. A loop-end switch and RETRIG both act on a step boundary and let the note finish through its gate.
- **RANDOM** (v0.14; since v0.15 in the EDIT row, after CLEAR and a divider line): fills the current slot's pattern with random notes and rests. The pattern gets as many steps as the **LOOP** knob says (with LOOP = ALL: the pattern's own length, or 16 steps if the slot is empty). Notes lie between C3 and C5 (60-84); with a **SCALE** set only tones of that scale (on the **ROOT**) are picked, so the grid shows exactly what you will hear; with SCALE off any semitone. Each step is a rest with a 25 % chance, rolled for every step separately, so the number and places of the rests change on every press (there is always at least one note). Only pitch and rest are filled: every other per-step value (probability, ratchet, gate, accent, octave chance, condition) is neutral. If the slot already holds a pattern you are asked first (REPLACE / CANCEL); other slots, the playing position and the settings are untouched. It works while the sequence plays (the new pattern is picked up at the next step; a sounding note ends normally). The result is an ordinary pattern: edit it, COPY it, save it with the project. SEED does not apply (each press is different); the 25 % and the C3-C5 range are fixed, not controls. The MIDI XPOSE transpose still moves the whole pattern when it is on.
- **Fix in v0.13.1:** loading a project while the sequencer held a note could leave that note droning until PLAY was pressed (found in Logic, Oct 9). The held note is now released.
- **dotriaconta-tone, the sequencer as a MIDI effect (v0.22, FIRST DRAFT)**: a second plugin built from the same sources (`WT8Seq` in CMake, compiled with `WT8_MIDI_FX=1`): an Audio Unit MIDI effect (type `aumi`) for Logic's MIDI FX slot above any instrument. It has the sequencer panel only (no sound controls, no presets, no audio) and sends the sequencer's notes out as MIDI on channel 1; notes played on the keyboard pass through unchanged (REC records them, MIDI XPOSE uses them as before), every other MIDI message passes through. Same sequencer, same saved pattern / slots / chain, nothing added. Tested on Linux with a headless test (`fx_test`: pattern order, spacing, note-offs on stop, pass-through, XPOSE, REC, saved state, odd block sizes) and a rendered picture of the window. NOT tested: loading and running in Logic (hosting as a MIDI effect, tempo / bar sync, the window, timing). The 22 sound parameters still exist inside it (they have no controls); it shares its parameter ids with ipmohc.
- **Presets** (v0.8; starter presets and the modified marker in v0.9): the row of controls at the top: `<` `>` step through the presets, the box lists them, **SAVE** asks for a name and stores the current sound, **FOLDER** opens the preset folder in Finder (delete or copy presets there). The list has three parts: **INIT** (puts every sound setting back to its default), the **STARTER** presets (Starter 01 to Starter 14, built into the plugin and read-only) and, under **USER**, your own saved presets. A preset stores the sound only: wavetable, frame, octave, pitch, attack, release, cutoff, resonance, delay/reverb, time, the four LFO settings and comp/sat; since v0.21 also the two LFO shapes, the filter type, KEY, VEL, FILT ENV and FILT DECAY (22 settings in all). A preset saved before v0.21, and every starter preset, does not mention the seven new ones, so loading it puts them at their defaults (DJ filter, Triangle, KEY / VEL / FILT ENV 0, FILT DECAY 40 %): the sound that preset always had. It does NOT store GAIN, PAN or BOOST (the level into the mixer), nor anything from the sequencer or the pattern. Your presets are small XML files (`*.ipmohcpreset`) in `~/Library/Application Support/particledots/ipmohc/Presets/` (Windows: `%APPDATA%\particledots\ipmohc\Presets`, Linux: `~/.config/particledots/ipmohc/Presets`), so they are available in every project and can be shared by copying the files. Loading a preset sets the parameters like moving the knobs (Logic can record it as automation); a setting the file does not mention goes to its default and a name this version does not know is ignored.
- **Modified marker** (v0.9): after you load or save a preset, its name stays in the box. If you then change any of the 22 sound settings it shows as **`* name` in amber**; put the knob back and the mark goes away. GAIN, PAN, BOOST, the sequencer and the pattern slots never count. To undo your changes, open the list and pick the same preset again (it loads again). A project that is opened shows no preset in the box: the sound came back with the project, not from a preset, so nothing is marked either.
- **Starter presets** (v0.9): these are NOT sounds I chose; I cannot listen to audio. They are the 14 sound presets that ship with the CHOMPI WAVE firmware (`firmware/card-profiles/wave-1.0/presets.json` in the CHOMPI repository, MIT, (c) CHOMPI Club; the licence notices stay with the repository), which were chosen by ear on the hardware. Each firmware number is handed to the same engine setter the plugin's parameter uses, so no value curve is involved. Differences: the pitch is rounded to a whole semitone (the firmware's pitch knob moves in semitones; six of the 14 are an octave up, one an octave down); there is no LFO on/off (all 14 have both LFOs on, and depth 0 is silent anyway); OCTAVE and COMP/SAT are not part of a firmware preset, so they load at their defaults (0 and 0). They are named by number only; to keep a variation, load one, change it and SAVE it under your own name (it then appears under USER). `StarterPresets.h` holds the firmware's numbers unchanged, and `plugin_test` checks them against the firmware file.
- Saving (v0.6): values that are not the default are added to the step as tags: `x3` ratchet, `g50` gate, `a` accent, `o30` octave chance, `c2/3` condition (pass 2 of every 3), e.g. `60:100:75:x3:g50:a:o30:c2/3` (a rest looks like `r:75:x3`). A pattern that uses none of them is saved exactly as before, so projects from v0.3 to v0.5 load unchanged (new values neutral, SWING 50 %, ACCENT 0.30, OCT JUMP "Up 1 octave"); a tag a future version adds is ignored when read.
- All sequencer settings (PLAY, SYNC, STEP, GATE, MUTE, LOOP, DIRECTION, ENDS x2, PROB, SEED, SCALE, ROOT, MIDI XPOSE, SWING, ACCENT, OCT JUMP) are automatable parameters (the transpose amount itself is not: it is set by keys or RESET). The v0.4 parameters have AU version hint 2, the v0.5 ones hint 3 and the v0.6 ones hint 4, so Logic keeps the order of the older ones. (The per-step values - ratchet, step gate, accent, octave chance, condition - are saved in the pattern and are not automatable.) Tests: `tests/seq_test.cpp` (exact sample timing, block-size independence, relocation, gate, mute, save/restore, direction orders, loop length, probability statistics, seed repeatability, bar-locking, the scale table and snapping, transpose, isRunning, the v0.6 save format, ratchet timing and cancelling, swing timing, per-step gate, accent, octave jumps, trigger conditions and pass counting, and a random "everything at once" run that checks notes always alternate on/off and the event buffer never fills) and `tests/plugin_test.cpp` (the same options through the real plugin, including the pitch that actually comes out for a scale and for MIDI XPOSE, ratchets, swing, accent, octave jumps and conditions as audio, saving, loading v0.3, v0.4 and v0.5 states).

## Loading your own wavetables (v0.10)

Under the WAVETABLE knob, **LOAD** puts a `.wav` file into the table slot the knob is on (1-7), replacing the built-in table in that slot; **RESET** brings the built-in one back. The knob's label then reads `USER: <file name>`. The file is converted when it is loaded (WAV only: PCM 8/16/24/32 bit or float, any sample rate, stereo is mixed to mono):
- a length that is a multiple of 2048 samples (the usual wavetable layout, e.g. Serum-style tables) is read as 2048-sample frames; a Serum-style `clm` chunk that announces another frame size is honoured;
- less than two frames' worth is read as one cycle (all 33 frames the same);
- anything else is treated as a recording and cut into 33 equal parts;
- more or fewer than 33 frames are mapped onto 33 (the first and last stay as they are, the ones between are blended); each frame has its DC offset removed and the table is scaled to peak 0.9, like the built-in ones.

After you pick the file, a small window asks for the **frame size** (v0.11): **Auto** (the default) does what is described above; 256, 512, 1024, 2048, 4096 or 8192 says how many samples one frame of the file has and overrides both the length rules and any `clm` marker. Use it when a table from another synth sounds like chopped-up audio because the file has no marker and its frames are not 2048 samples long. If the file length is not a whole number of frames, the left-over samples at the end are ignored (the alert says so).

Next to the oscillator knobs a small picture (v0.12) shows the table in the selected slot: the frame at the FRAME knob, large, and all 33 frames below it as a stack (frame 0 in front, the current frame lit). It follows the WAVETABLE and FRAME knobs, host automation, LOAD and RESET. It is display only (no mouse). The knobs in the OSCILLATOR group are a little narrower to make room, so a long file name in the `USER:` label is cut off earlier.

A loaded table is stored **inside the project** (about 350 KB per slot in the saved state), so the project does not depend on the file afterwards. A preset only stores the TABLE number, not the table. The engine still holds 7 tables (the firmware's limit), so a loaded table replaces one slot.

## Wavetable maker (tools/make_wavetables.py)

A small Python script (needs `numpy`; runs on Mac and Windows) that writes wavetables in the format the engine reads: mono 32-bit float WAV, 33 frames of 2048 samples, peak 0.9. `morph` blends two waveforms across the 33 frames, `sweep` opens one waveform from a sine to full brightness, `slice` cuts a recording into 33 frames, `convert` turns an external wavetable into this format (LOAD does that itself, so `convert` is only needed to prepare files in advance), and `check` reports whether a `.wav` is usable. Run it with `--help` for the options. Load its output with LOAD.

## Known limitations / things to verify
- **Pitch.** The firmware plays MIDI note 60 at 130.81 Hz (an octave below most synths). ipmohc adds +12 semitones in `WT8Engine::noteOn` so MIDI 60 = 261.63 Hz; `tests/rate_test.cpp` checks this to within 3 cents at 44.1, 48 and 96 kHz. Octave +1 / -1 still shifts by an octave from there.
- **Sample rate.** The firmware counts delay length in samples at 48 kHz. The engine now scales the delay length and memory by host rate / 48000 (one small change in `Source/engine/subtractiveEngine.h`), so delay time in seconds is the same at every rate. Reverb size and LFO speeds are not yet verified across rates.
- **Sample rate.** The firmware runs at 48 kHz; some constants (parameter smoothing, the 960-sample wavetable crossfade, the delay buffer length) were tuned for that, so at 44.1 / 96 kHz timing shifts slightly. Not tested at 96 kHz.
- **Block size.** The engine processes 24-sample blocks as on hardware; key requests are applied between blocks (sub-millisecond).
- Velocity -> level follows the firmware (vel+1)/127.

## Tests (headless, no audio hardware)
- `render_test`: loads the 7 wavetables, plays a note, a chord with a frame sweep, and a reverb tail; checks for finite output, sane level, and silence after release. Writes a WAV.
- `plugin_test`: instantiates the real plugin, sends MIDI through `processBlock` at 44.1 kHz / 512 samples, checks sound and release, and round-trips state.

## How it's put together
```
Source/engine/    UNMODIFIED copies of the CHOMPI WAVE DSP headers (from firmware/chompi-wave/code/src)
Source/shim/      tiny stand-ins for libDaisy's daisy.h, FIFO (copied), FatFs and the SD file queue
Source/WT8Engine  JUCE-free wrapper: params -> engine setters, MIDI -> key requests, render(), WAV loading
Source/PluginProcessor  JUCE glue: parameters, MIDI timing, state, generic editor
third_party/DaisySP  DaisySP (MIT, Electrosmith), used as-is
wavetables/       the 7 wavetable WAVs from the CHOMPI repo
```
